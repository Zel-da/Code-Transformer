**[복사 시작]**

너는 수산세보틱스 디지털혁신팀의 시니어 시스템 아키텍트이자 풀스택 리드 개발자야. 현재 운영 중인 '공정 부적합 보고 시스템(As-Is)'을 비즈니스 전략에 맞춰 'V2.0(To-Be)'으로 고도화하는 핵심 프로젝트를 총괄하고 있어.

아래 제공되는 [비즈니스 요구사항(To-Be 전략)]과 [현재 시스템 명세(As-Is)]를 완벽히 숙지하고, 개발팀과 현장 작업자가 즉시 활용할 수 있는 [V2.0 시스템 고도화 설계 명세서]를 도출해 줘.

### [비즈니스 요구사항 (To-Be 전략)]

1. **생산 팀장 승인 단계 생략**: 의사결정 리드타임을 단축하고 QC 실무자에게 실물 확인 및 판정 전결권 부여.
2. **워크플로우 분기**: 현장 작업자가 초기 입력 시 '양산품 vs 개발품'을 구분. 개발품 등록 시 연구소 담당자에게 다이렉트로 전파되어 설계 검토 병행.
3. **수산톡(SushanTalk) 하이브리드 전파**: 기존 앱 푸시 알림과 함께 시스템이 자동으로 상세 페이지 링크를 사내 메신저(수산톡)로 발송하여 정보의 즉시성 확보.
4. **24시간 피드백 SLA 로직**: 연구소/구매팀 등 유관 부서 전파 후 24시간 이내에 의견 등록이 없을 경우, 데이터 수정을 제한(Lock)하고 QC의 판정 결과를 최종 확정 처리하여 데이터 무결성 유지.

### [현재 시스템 명세 (As-Is)]

* **로그인 (/login)**: JWT 발급, localStorage 저장, role(admin/worker)에 따른 자동 라우팅.
* **보고서 작성 (/submit)**:
* 공장/공정, 발생/입력일, 불량유형(마스터데이터), 제품코드(300ms 디바운스 자동완성), 부적합 현상, 불량 사진 등 입력.
* 불량 사진은 500KB 이하 압축 후 Object Storage에 Presigned URL로 직접 PUT 업로드.
* 성공 시 `POST /api/reports` 호출 및 폼 초기화.


* **대시보드 (/admin)**: 상단 통계 카드 4개(전체/PENDING/FAILED/COMPLETED), 상태/날짜 필터. 데스크탑은 테이블/슬라이드 패널(Sheet), 모바일은 카드 리스트/드로어(Drawer) 구조로 상세 내용 확인.
* **관리자 패널 (/manage)**: 사용자 계정 관리(CRUD), 보고서 전체 내용 수정 및 삭제 기능.
* **RPA 동기화**: `POST /api/rpa/trigger` 호출 시 PENDING 상태 보고서 일괄 처리.
* **공통**: TanStack Query 기반 데이터 무효화(invalidate)로 상태 자동 갱신. 모바일/데스크탑 반응형.

### 💡 Task : V2.0 고도화를 위한 시스템 설계 명세서 산출

위 맥락을 바탕으로 다음 4가지 영역에 대한 상세한 아키텍처 및 개발 명세서를 마크다운 형식(표, 코드 블록, 불릿 포인트 활용)으로 작성해 줘.

**1. 데이터베이스 스키마 및 REST API 엔드포인트 설계**

* To-Be 전략(양산/개발 구분, 수산톡 발송 여부, 24시간 SLA 타임스탬프, QC 최종 조치결과 및 Lock 상태 등)을 수용하기 위해 **기존 DB Report 테이블에 추가되거나 변경되어야 할 컬럼 스키마**를 표로 정리해 줘.
* 프로세스 변경에 따라 신규로 개발하거나 수정해야 할 **API 엔드포인트 명세** (Method, URI, Request/Response 요약, 설명).

**2. 프론트엔드(UI/UX) 컴포넌트 및 상태 관리 로직 변경**

* `/submit` 폼 최상단에 추가될 '양산/개발' 선택 UI와, 라벨 기반 제품코드 입력 가이드를 포함한 모바일 최적화 레이아웃 방안.
* `/manage` 상세 패널(Sheet/Drawer)에 QC 담당자가 현장 확인 후 조치 결과(반출/수정, 손실공수 등)를 확정 짓는 입력 UI 및 권한 제어(Role-based) 동선.
* 새로운 액션(SLA 확정, QC 조치) 완료 후 TanStack Query의 `invalidateQueries` 호출 흐름.

**3. 백엔드 비동기 처리: 수산톡 연동 및 24시간 SLA 스케줄러 아키텍처**

* `POST /api/reports` 성공 시, 클라이언트 응답 지연 없이 비동기(Async/Event-driven)로 수산톡 웹훅 API를 호출하여 상세 링크를 발송하는 서버 사이드 흐름.
* '24시간 SLA'를 구현하기 위해 시스템 스케줄러(Cron/Worker)가 주기적으로 PENDING/처리중 상태의 데이터를 체크하고 Lock 상태로 업데이트하는 로직 설계.

**4. RPA 동기화 안정성 확보 및 예외 처리 (Exception Handling)**

* `POST /api/rpa/trigger` 실행 시, 기존 ERP 시스템 부하나 네트워크 지연으로 인해 발생할 수 있는 주요 **장애 시나리오(Edge Cases) 2가지**.
* 동기화 실패(FAILED) 건 발생 시의 재시도(Retry) 메커니즘 설계 및 관리자 대시보드 내 인지/수동 처리 방안.
