# 수산톡 봇 메시지 & 인터랙티브 액션 API — 완전 레퍼런스

> 대상 독자: 수산톡 외부 연동을 처음 구현하는 개발자 또는 AI  
> 이 문서만 읽으면 알림봇·인터랙티브 버튼봇을 완전히 구현할 수 있다.

---

## 1. 기본 개념

### 봇 계정 자동 생성
외부 API로 메시지를 보내면 **`botName` 값으로 봇 계정이 자동 생성**된다.  
직접 봇 계정을 만들 필요가 없다.

- 이메일: `bot-{botName}@soosan.internal` (예: `bot-ERP-봇@soosan.internal`)
- 로그인 불가 계정 (password_hash가 bcrypt 형식이 아닌 랜덤값)

### 채널 구조
봇이 DM을 보내면 수신자 수신함에 **`type='bot'` 방**이 생성된다.

| 방 타입 | 설명 |
|--------|------|
| `direct` | 1:1 DM (일반 사용자 간) |
| `group` | 그룹 채팅 |
| `channel` | 공개 채널 |
| `bot` | 봇 DM 알림 채널 (봇 + 사용자) |

## 2. 인증 — Personal Access Token (PAT)

### 토큰 형식
```
sst_{64자리 hex}
```
예: `sst_a1b2c3d4e5f6...`

### 요청 방법
모든 외부 API 요청에 HTTP 헤더로 전달:
```
Authorization: Bearer sst_xxx
```

### 스코프 종류

| 스코프 | 용도 |
|--------|------|
| `message:write` | 봇 메시지 전송 (DM·채널·다수발송), 전송이력 조회 |
| `calendar:write` | 자신의 캘린더 이벤트 등록 |
| `calendar:read` | 자신의 캘린더 이벤트 조회 |
| `calendar:service` | 서버-서버 마스터 PAT (타 사용자 캘린더 접근, PAT 대리 발급) |
| `me:read` | 내 프로필 조회, 나의 공간 메모 저장 |

### PAT 발급 방법 (관리자)
수산톡 어드민 대시보드 → 설정 → API 토큰 관리 → 새 토큰 발급  
`message:write` 스코프 선택 → 생성 → 토큰 값 복사 (이 화면에서만 확인 가능)

### PAT 대리 발급 (서버-서버, calendar:service 전용)
```http
POST /api/external/v1/user-tokens
Authorization: Bearer {마스터_PAT}
Content-Type: application/json

{
  "targetEmail": "user@soosan.co.kr",
  "scopes": ["me:read", "calendar:read", "calendar:write"],
  "name": "수산메일 자동 연동",
  "expiresInDays": 365
}
```
응답:
```json
{
  "token": "sst_xxx",        // 평문 — 이 응답에서만 노출. 반드시 저장
  "tokenId": 42,
  "userId": 1430,
  "email": "user@soosan.co.kr",
  "scopes": ["me:read", "calendar:read"],
  "expiresAt": "2027-06-15T...",
  "alreadyExisted": false     // true면 token은 null (기존 토큰 재사용)
}
```
> **중복 방지**: 동일 `name`으로 유효 토큰이 이미 있으면 재발급 없이 `alreadyExisted: true` 반환

## 3. 봇 메시지 전송 API

**엔드포인트**: `POST /api/external/v1/messages`  
**스코프**: `message:write`  
**Base URL**: `https://{REPLIT_DOMAIN}` (예: `https://수산톡.replit.app`)

---

### 3-A. 단건 DM 전송

수신자를 **이메일 / 사원번호 / 이름+부서** 중 하나로 지정한다.

```http
POST /api/external/v1/messages
Authorization: Bearer sst_xxx
Content-Type: application/json

{
  "toEmail": "gildong.hong@soosan.co.kr",
  "content": "결재 요청이 도착했습니다.",
  "botName": "ERP 봇",
  "roomName": "📋 ERP 알림"
}
```

| 수신자 지정 방법 | 필드 |
|---------------|------|
| 이메일 | `toEmail` |
| 사원번호 | `toEmployeeId` |
| 이름 + 부서 | `toName` + `toDept` |

공통 선택 파라미터:

| 파라미터 | 기본값 | 설명 |
|---------|--------|------|
| `content` | **(필수)** | 메시지 본문, 최대 4000자 |
| `botName` | `"수산톡 시스템"` | 봇 표시명. 처음 사용 시 계정 자동 생성 |
| `roomName` | `"🔔 알림"` | DM 알림 채널 표시명 |
| `contentType` | `"text"` | `"text"` 또는 `"system"` |
| `actions` | 없음 | 인터랙티브 버튼 배열 (§4 참고) |

응답:
```json
{ "ok": true, "messageId": 1234, "roomId": 56 }
```

---

### 3-B. 다수 수신자 일괄 전송

`recipients` 배열로 최대 100명에게 같은 메시지를 한 번에 보낼 수 있다.

```http

Authorization: Bearer sst_xxx
Content-Type: application/json

{
  "recipients": [
    { "toEmail": "alice@soosan.co.kr" },
    { "toEmployeeId": "S20241001" },
    { "toName": "홍길동", "toDept": "개발팀" }
  ],
  "content": "오늘 15시 전사 회의가 있습니다.",
  "botName": "그룹웨어 봇"
}
```

응답:
```json
{
  "ok": true,
  "sent": [
    { "userId": 101, "email": "alice@soosan.co.kr", "name": "Alice", "messageId": 1001, "roomId": 201 }
  ],
  "failed": [
    { "spec": { "toName": "홍길동", "toDept": "개발팀" }, "error": "User not found" }
  ]
}
```

## 4. 인터랙티브 액션(버튼) 메시지

메시지에 `actions` 배열을 포함하면 수신자 화면에 **클릭 가능한 버튼**이 표시된다.

### 4-A. MessageAction 타입 정의

```typescript
interface MessageAction {
  id: string;                          // 같은 메시지 내에서 유일한 버튼 ID
  label: string;                       // 버튼 표시 텍스트
  value: string;                       // postback 값 또는 URL (type에 따라 다름)
  style?: "default" | "primary" | "danger";  // 버튼 색상 스타일
  type?: "postback" | "url";           // 기본값: "postback"
  callbackUrl?: string;                // postback 타입 전용: 클릭 시 POST 받을 URL
}
```

### 4-B. type별 동작 차이

| type | 클릭 시 동작 | 서버 기록 | callbackUrl |
|------|------------|---------|-------------|
| `postback` (기본) | 서버에 응답 기록 → callbackUrl로 POST 전송 | ✅ | 선택 |
| `url` | `value`를 새 탭으로 열기 | ❌ | 무시됨 |

### 4-C. 제약 조건
- 버튼 최대 **5개**
- **사용자 1인당 1회**만 응답 가능 (재응답 시 `409 Conflict`)
- 다른 사용자들은 **독립적으로 각자 응답** 가능 (per-user 추적)
- 응답 후 취소/변경 불가

### 4-D. 전송 예시

```http
POST /api/external/v1/messages
Authorization: Bearer sst_xxx
Content-Type: application/json

{
  "toEmail": "gildong.hong@soosan.co.kr",
  "botName": "회의 봇",
  "roomName": "📅 회의 알림",
  "content": "내일 14시 주간 회의 참석 여부를 선택해주세요.",
  "actions": [
    {
      "id": "attend",
      "label": "✅ 참석",
      "value": "attend",
      "style": "primary",
      "type": "postback",
      "callbackUrl": "https://your-server.com/webhook/meeting-rsvp"
    },
    {
      "id": "absent",
      "label": "❌ 불참",
      "value": "absent",
      "style": "danger",
      "type": "postback",
      "callbackUrl": "https://your-server.com/webhook/meeting-rsvp"
    },
    {
      "id": "agenda",
      "label": "📋 회의 안건 보기",
      "value": "https://docs.example.com/agenda-2026-06-16",
      "type": "url"
    }
  ]
}
```

## 5. 버튼 클릭 웹훅 (callbackUrl 수신)

사용자가 `postback` 버튼을 클릭하면 수산톡 서버가 `callbackUrl`로 HTTP POST를 보낸다.

### 수신 페이로드

```http
POST https://your-server.com/webhook/meeting-rsvp
Content-Type: application/json

{
  "messageId": 1234,
  "userId": 101,
  "actionId": "attend",
  "value": "attend",
  "name": "홍길동",
  "email": "gildong.hong@soosan.co.kr",
  "triggeredAt": "2026-06-15T14:23:11.000Z"
}
```

| 필드 | 타입 | 설명 |
|------|------|------|
| `messageId` | number | 수산톡 메시지 ID |
| `userId` | number | 클릭한 사용자의 수산톡 user_id |
| `actionId` | string | 클릭된 버튼의 `id` |
| `value` | string | 버튼의 `value` 값 |
| `name` | string | 클릭한 사용자 이름 |
| `email` | string | 클릭한 사용자 이메일 |
| `triggeredAt` | ISO8601 | 클릭 시각 |

### 웹훅 처리 규칙
- 수산톡은 콜백을 **10초 타임아웃**으로 POST 후 응답 상태를 로그에 기록
- 콜백 실패해도 수산톡은 메시지 처리를 **롤백하지 않음** (fire-and-forget)
- 콜백 서버는 **빠른 응답**(`2xx`) 후 비동기 처리 권장

## 6. 버튼 클릭 내부 처리 흐름

프론트엔드가 버튼을 클릭하면 수산톡 내부 API로 처리된다.  
(외부 개발자가 직접 호출할 필요 없음 — 참고용)

```http
POST /api/messages/{messageId}/action
Authorization: Bearer {JWT}
Content-Type: application/json

{ "actionId": "attend" }
```

처리 순서:
1. 메시지에서 `actions` JSONB 조회
2. 해당 `actionId` 존재 여부 확인
3. `actions_triggered[userId]` 존재 시 `409` 반환 (중복 방지)
4. `actions_triggered` JSONB에 `{ [userId]: { actionId, value, name, email, triggeredAt } }` 병합
5. `callbackUrl` POST (비동기, 실패 무시)
6. Socket.io `message-update` 이벤트로 방 전체 브로드캐스트

## 8. DB 스키마 (참고)

### messages 테이블 관련 컬럼

| 컬럼 | 타입 | 설명 |
|------|------|------|
| `actions` | `jsonb` | MessageAction[] 배열 |
| `actions_triggered` | `jsonb` | `{ [userId: string]: TriggeredEntry }` |
| `sender_id` | `integer` | 봇 계정의 user_id |
| `content_type` | `text` | `'text'` 또는 `'system'` |

### actions_triggered 포맷

```json
{
  "101": {
    "actionId": "attend",
    "value": "attend",
    "name": "홍길동",
    "email": "gildong.hong@soosan.co.kr",
    "triggeredAt": "2026-06-15T14:23:11.000Z"
  },
  "205": {
    "actionId": "absent",
    "value": "absent",
    "name": "김철수",
    "email": "chulsoo.kim@soosan.co.kr",
    "triggeredAt": "2026-06-15T14:30:05.000Z"
  }
}
```

키는 `userId` 문자열. JSONB `||` 연산자로 사용자별 독립 병합.

## 9. 나의 공간 메모 전송 (self-notes)

```http
POST /api/external/v1/self-notes
Authorization: Bearer sst_xxx
Content-Type: application/json

{
  "content": "오늘 작성한 일일 업무 보고서가 수산메일에 저장되었습니다.",
```

- `calendar:service` 스코프: `targetEmail`로 지정한 타 사용자 나의 공간에 저장

응답:
```json
{ "ok": true, "messageId": 777, "roomId": 88, "targetEmail": "user@soosan.co.kr" }
```

## 10. 완성된 알림봇 구현 예시

### 10-A. 결재 요청 알림 (postback 버튼)

```javascript
const BASE_URL = "https://수산톡.replit.app";
const PAT = process.env.SUSAN_TALK_PAT; // sst_xxx

async function sendApprovalRequest({ approverEmail, documentTitle, documentUrl, requesterId }) {
  const res = await fetch(`${BASE_URL}/api/external/v1/messages`, {
    method: "POST",
    headers: {
      "Authorization": `Bearer ${PAT}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify({
      toEmail: approverEmail,
      botName: "전자결재 봇",
      roomName: "📝 결재 요청",
      content: `[결재 요청] ${documentTitle}\n\n요청자: ${requesterId}\n문서를 검토 후 승인/반려해 주세요.`,
      actions: [
        {
          id: "approve",
          label: "✅ 승인",
          value: "approved",
          style: "primary",
          type: "postback",
          callbackUrl: `${process.env.MY_SERVER}/webhooks/approval`,
        },
        {
          id: "reject",
          label: "❌ 반려",
          value: "rejected",
          style: "danger",
          type: "postback",
          callbackUrl: `${process.env.MY_SERVER}/webhooks/approval`,
        },
        {
          id: "view",
          label: "📄 문서 보기",
          value: documentUrl,
          type: "url",
        },
      ],
    }),
  });
  return await res.json(); // { ok: true, messageId, roomId }
}
```

### 10-B. 웹훅 수신 서버 (Express 예시)

```javascript
app.post("/webhooks/approval", express.json(), async (req, res) => {
  const { messageId, userId, actionId, value, name, email, triggeredAt } = req.body;

  // 빠른 200 응답 (수산톡 10초 타임아웃 이전에)
  res.sendStatus(200);

  // 비동기 처리
  await db.update("approval_requests")
    .set({
      status: value,           // "approved" | "rejected"
      approverEmail: email,
      approverName: name,
      decidedAt: triggeredAt,
    })
    .where({ suisanTalkMessageId: messageId });

  // 결과 통보 (요청자에게)
  if (value === "approved") {
    await notifyRequester({ approverName: name, result: "승인" });
  } else {
    await notifyRequester({ approverName: name, result: "반려" });
  }
});
```

### 10-D. 다수 대상 설문

```javascript
async function sendSurvey(emailList, question, options) {
  const actions = options.map((opt, i) => ({
    id: `opt_${i}`,
    label: opt.label,
    value: opt.value,
    style: i === 0 ? "primary" : "default",
    type: "postback",
    callbackUrl: `${process.env.MY_SERVER}/webhooks/survey`,
  }));

  const res = await fetch(`${BASE_URL}/api/external/v1/messages`, {
    method: "POST",
    headers: { "Authorization": `Bearer ${PAT}`, "Content-Type": "application/json" },
    body: JSON.stringify({
      recipients: emailList.map(email => ({ toEmail: email })),
      botName: "설문 봇",
      roomName: "📊 사내 설문",
      content: question,
      actions,  // 최대 5개
    }),
  });
  const data = await res.json();
  console.log(`발송 성공: ${data.sent.length}명, 실패: ${data.failed.length}명`);
}

// 사용 예
await sendSurvey(
  ["alice@soosan.co.kr", "bob@soosan.co.kr"],
```

## 11. 에러 코드 정리

| HTTP | 코드 | 원인 | 해결 |
|------|------|------|------|
| 401 | `Bearer token required` | Authorization 헤더 없음 | 헤더 추가 |
| 401 | `Invalid token` | 잘못된 PAT | 토큰 재확인 |
| 401 | `Token expired` | 만료된 PAT | 어드민에게 재발급 요청 |
| 403 | `Scope 'X' required` | 스코프 미보유 | 올바른 스코프로 토큰 발급 |
| 400 | `content is required` | content 빈값 | content 필드 추가 |
| 400 | `actions는 최대 5개` | 버튼 6개 이상 | 5개 이하로 제한 |
| 400 | `type은 'postback' 또는 'url'` | 잘못된 type 값 | `"postback"` 또는 `"url"` 사용 |
| 404 | `User not found` | 수신자 없음 | 이메일/사원번호 재확인 |
| 404 | `채널을 찾을 수 없음` | 채널명 오타 | 수산톡 채널 목록 확인 |
| 409 | `Already responded` | 이미 버튼 클릭 | 한 사용자 1회 응답 제한 |

## 13. 전체 API 엔드포인트 요약

| 메서드 | 경로 | 스코프 | 설명 |
|--------|------|--------|------|
| `GET` | `/api/external/v1/me` | `me:read` | 내 프로필 조회 |
| `GET` | `/api/external/v1/messages` | `message:write` | 봇 전송 이력 조회 |
| `POST` | `/api/external/v1/messages` | `message:write` | 봇 메시지 전송 (DM/채널/다수) |
| `POST` | `/api/external/v1/self-notes` | `me:read` 또는 `calendar:service` | 나의 공간 메모 |
| `GET` | `/api/external/v1/calendar/events` | `calendar:read` | 캘린더 이벤트 조회 |
| `POST` | `/api/external/v1/calendar/events` | `calendar:write` | 캘린더 이벤트 등록 |
| `DELETE` | `/api/external/v1/calendar/events/:id` | `calendar:write` | 캘린더 이벤트 삭제 |
| `DELETE` | `/api/external/v1/calendar/events` | `calendar:write` | 캘린더 이벤트 전체 삭제 |
| `POST` | `/api/external/v1/user-tokens` | `calendar:service` | 사용자 PAT 대리 발급 |
| `POST` | `/api/messages/:id/action` | JWT (일반 사용자) | 버튼 클릭 처리 (내부용) |
