1. 프로그램 시작

바탕화면의 "NCR RPA" 아이콘을 더블클릭하면 끝.

(아이콘이 없으면 rpa-ncr 폴더의 시작.bat 파일을 더블클릭. 처음 한 번만 바탕화면에 바로가기 만들기.bat 을 실행하면 다음부터는 바탕화면에서 바로 켤 수 있습니다.)

첫 실행 시: 검은 콘솔 창이 뜨면서 "필요한 프로그램을 자동 설치합니다" 메시지가 나옵니다. 인터넷이 연결돼 있으면 2~3분 정도 기다리면 자동으로 진행되고, 끝나면 브라우저가 열립니다.
2회차부터는 설치 단계 없이 몇 초 만에 바로 열립니다.

아래와 같은 콘솔이 뜨면 정상:

==================================================
  NCR → UNIERP RPA 자동 입력 서버
  http://127.0.0.1:8010

  ※ 이 창을 닫으면 서버가 종료됩니다
==================================================

기본 브라우저가 http://127.0.0.1:8010 으로 자동 오픈됩니다.

주의: 검은 콘솔 창을 닫으면 서버가 같이 꺼집니다. 작업 중에는 콘솔을 그대로 두세요 (최소화는 OK).

2. 대시보드 화면 구성

번호섹션역할
①설정 점검 배너필수 설정 누락 시 빨간 경고, 정상이면 ✓ 표시. 설치 직후 한 번만 확인.
②데이터 소스리플릿 API / Neon DB 중 어디서 보고를 받아올지 선택 (보통 공용 DB).
③ERP 설정UNIERP 창 제목·실행경로·로그인PW 등. 한 번 맞춰두면 안 건드림.
④실행PENDING 조회 / ERP 창 확인 / 입력 시작·일시정지·중지.
⑤큐현재 처리할 보고 목록과 상태(대기/진행/완료/실패).
⑥실시간 로그RPA가 한 줄씩 무슨 작업을 하는지 라이브 출력.

② 데이터 소스

  • 공용 DB (Neon) 를 선택한 상태가 기본입니다.
  • 연결 테스트 누르면 "DB 연결 OK (Neon)" 메시지가 떠야 정상.
  • 실패 시 → PRIVATE/app_db.json 파일이 있는지, 인터넷 연결이 되는지 확인.

③ ERP 설정

항목값

로그인 비밀번호직장님 ERP 비밀번호 (비워두면 본인이 직접 로그인 필요)

변경한 뒤 ERP 설정 저장 클릭.

④ 실행 / ⑤ 큐 / ⑥ 실시간 로그

버튼동작

중지 즉시 중단. 처리 중이던 보고는 PENDING으로 복원.

3. 일상 사용 흐름 (4단계)

요약: ① UNIERP 켜고 로그인 → ② 부적합등록(S) 폼 직접 한 번 열기 → ③ 대시보드에서 PENDING 조회 → ④ 입력 시작 → 검토 → 완료 확인.

1UNIERP 준비

  1. UNIERP를 평소대로 실행하고 로그인.
  2. 메뉴찾기(F3)에서 부적합등록(S) 검색해 폼을 한 번 띄워둡니다.
    ※ 이미 열려있으면 RPA가 중복 탭을 안 열고 그대로 사용합니다.

2PENDING 조회

  1. 대시보드에서 PENDING 조회 클릭.
  2. 큐 테이블에 보고 건수가 채워지면 성공.
  3. 건수가 0건 이면 현재 처리할 신규 보고가 없다는 뜻 — 그냥 종료해도 됨.

3입력 시작

  1. ERP 창 확인 한 번 눌러서 "UNIERP 메인 창 찾음" 메시지 확인.
  2. 입력 시작 클릭.
  3. 실시간 로그에 한 줄씩 진행 상황이 흐릅니다 (예: #7 공정: 'A01' 입력 OK).
  4. 마우스를 건드리지 말고 끝날 때까지 대기 — 다른 창 클릭하면 자동 중지됩니다.
RPA 도는 중 금지 행위: 마우스 클릭, 키보드 입력, 창 전환, 채팅·메일·브라우저 확인. 잠깐 자리 비울 시간을 두고 시작하세요. (1건당 약 30~60초 예상)

4검토 → 완료 확인

한 보고의 입력이 끝나면 자동으로 검토 패널이 열립니다 (다음 섹션 참고). 다 맞으면 완료 확인 → DB에 COMPLETED 마킹 → 다음 보고로 진행.

4. 검토 워크플로 — 어긋난 항목만 재실행

RPA가 17개 필드를 다 채운 뒤 화면이 다음과 같이 바뀝니다:

#필드값방법재실행
1발행팀코드SH11610100type재실행 #1
2부적합구분3dropdown재실행 #2
...(총 17행)

위에 다음 두 버튼:

  • 처음부터 — 17개 필드 전부 다시 (폼 새로 열어서 시작)
  • 완료 확인 — 다 맞다고 판정. 서버에 COMPLETED 통보 후 다음 보고로

검토 절차

  1. UNIERP 폼을 직접 눈으로 확인. 17개 필드가 다 제대로 들어갔는지 본다.
  2. 어긋난 필드가 있으면 → 해당 행의 재실행 #N 클릭.
    • 해당 필드 위치만 다시 클릭하고 값 재입력.
    • 잘 들어가면 다음 어긋난 항목 찾아 같은 식으로.
  3. 전체적으로 위치가 다 어긋났으면 → 처음부터 (폼을 닫고 새로 열어 처음부터).
  4. 다 맞으면 → 완료 확인.
    이때 비로소 서버 DB에 sync_status = COMPLETED 가 기록됩니다.
    완료 확인을 누르지 않으면 PENDING으로 남아 다음에 또 처리 대상이 됩니다.
왜 이렇게 만들었나? RPA가 "다 했다"고 자기 판단으로 COMPLETED 마킹하면, 사실은 위치가 어긋나 빈 칸으로 저장돼도 서버는 완료된 줄 알게 됩니다. 사람 눈으로 한 번 더 확인하는 안전장치입니다.

5. 일시정지·중지

버튼동작언제 쓰나
일시정지/재개 현재 키 입력 끝낸 뒤 다음 단계 직전에 대기. 한 번 더 누르면 재개. 잠깐 다른 일 처리해야 할 때 (전화·확인 등). 보고 처리 상태는 그대로 유지.
중지 즉시 중단. 처리 중이던 보고는 PENDING으로 복원되어 다음에 다시 처리 가능. 뭔가 잘못됐을 때 / 강제로 끊고 싶을 때.
자동 중지: RPA가 도는 중에 다른 창을 클릭하거나 ERP 창이 백그라운드로 가면 포커스 보호 기능이 작동해 자동으로 멈춥니다. (의도하지 않은 입력 사고 방지)

6. 자주 발생하는 상황

상황 1 — "ERP 창을 찾을 수 없습니다"

  • UNIERP가 켜져 있는지 확인. 없으면 직접 실행 후 다시 시도.
  • Chrome에 "UNIERP" 글자가 있는 탭이 켜져 있으면 혼동될 수 있으나, 프로세스명(Bizentro) 필터로 거른다 → 보통 문제 없음.

상황 2 — 입력값에 ERP가 모르는 코드라 검색창이 뜬다

RPA가 일시정지 상태로 들어갑니다. 사용자가 직접:

  1. 검색창에서 정확한 값을 선택해 닫기.
  2. 대시보드의 일시정지/재개 한 번 더 눌러 재개.

매번 같은 코드에서 막힌다면 DB의 마스터 동기화 점검 (item_groups, vendors, processes).

상황 3 — 입력 위치가 1~2 픽셀 어긋남

  • 해상도 차이 때문일 수 있음. 검토 패널에서 해당 필드만 재실행하면 보통 잘 들어감.
  • 매번 어긋난다면 본사에서 config/field_mapping.json 의 좌표 재캘리브레이션 필요.

상황 4 — ERP에 에러창이 뜬다

RPA가 자동으로 에러창을 닫고 처리 종료. 어떤 필드에서 났는지 로그에 기록됨. 같은 보고가 PENDING으로 복원되며, 다음 회차에 재시도되지만 같은 데이터면 또 실패 가능 — 데이터 자체 점검 필요.

상황 5 — 한 보고만 계속 실패 (FAILED 상태)

큐 테이블에 "실패" 표시된 보고. 더블클릭으로 펼쳐서 오류 원인 로그 확인:

  • 품목코드가 ERP에 없는 경우 → 본사에 등록 요청.
  • 거래처가 valid_flg=N인 경우 → 마스터 데이터 점검.
  • 로그 확인 후 직접 ERP에 수기 입력하는 게 빠를 수 있음.

7. 프로그램 종료

  1. 현재 진행 중인 보고가 있으면 끝까지 (혹은 중지) 마무리.
  2. 브라우저 탭은 그냥 닫아도 됨 (UI만 사라짐, 서버는 계속 떠있음).
  3. 완전히 끄려면 콘솔(검은 창)에서 Ctrl + C 또는 콘솔 창 우상단 X 버튼.
