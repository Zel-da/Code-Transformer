# 공정 부적합 등록 가이드라인

> **대상**: 아산·화성 공장 **생산 작업자** 및 **품질(QC) 담당자**
> **근거**: 2026-11-12 화성 공정부적합 등록 업무개선 미팅 결론
> **목적**: 공장 간 업무 절차 통일, 입력 부담 최소화, 데이터 품질 확보

---

## 1. 등록 원칙 (언제 등록하는가)

> **"현장에서 조치·판정이 끝난 뒤 등록한다."**

- **즉시 올리지 않는다.** 불량 발생 → 품질 확인 → 조치 결정(수정/반출/폐기 등) → 그때 등록.
- 공정 부적합의 "접수" 성격보다 **"판정 완료 후 기록"** 의 성격이 큼.
- 알림을 수신한 품질(QC) 담당자가 현장에 와서 **같이 확인**하는 과정이 선행되어야 한다.
- 긴급 상황은 기존대로 전화·슈산톡으로 1차 전파하고, 조치 결정 후 등록으로 마무리.

### 어떤 수준의 불량을 등록하나

| 수준 | 등록 | 설명 |
|---|:-:|---|
| 작업자가 즉시 수정 가능한 공산품 수준 (볼트 재조임 등) | ❌ | 등록하지 않음. 작업 내 흡수. |
| 품질·설계 확인이 필요한 수준 | ✅ | 등록 대상 |
| 부품 교체·외주 반출 수정이 필요한 수준 | ✅ | 등록 대상 |
| 재작업·폐기 결정이 필요한 수준 | ✅ | 등록 대상 |
| A/S 재공정 중 발견된 추가 불량 | ✅ | 공정 부적합으로 등록 (비고란에 "A/S 재공정 중" 명시) |

## 2. 공장별 입력 항목 (생산 작업자)

### 2-1. 아산 공장 (SA00)

ERP 기반 제품품번 조회가 가능한 환경. 기존 방식 유지.

| 항목 | 필수 | 설명 |
|---|:-:|---|
| 양산/개발 | ✅ | 선택 |
| 공장 | ✅ | 자동 (아산) |
| 공정 | ✅ | 드롭다운 선택 |
| **제품품번** | ✅ | ERP 자동 조회 또는 수기 입력 |
| 제품명 | — | 자동 채움 (수정 가능) |
| 호기 | — | 해당 시 입력 |
| 부적합 현상 | ✅ | 자유 서술 |
| 사진·영상 | — | 최대 10개 (ERP 기준) |

### 2-2. 화성 공장 (SH00)

제품품번 체계가 아산과 다르고 작업자가 ERP 품번 찾기 어려움 → **기종명·부품명 수기 입력**이 기본.

| 항목 | 필수 | 설명 |
|---|:-:|---|
| 양산/개발 | ✅ | 선택 |
| 공장 | ✅ | 자동 (화성) |
| 공정 | ✅ | 드롭다운 선택 (추가팀 포함) |
| **기종명** | ✅ | 수기 입력 (예: SB-100, JD-1400E, 실린더바디) |
| **부품명** | ✅ | 수기 입력 (예: 로드핀, 커버, 플레이트) |
| 부품코드 | — | 알면 입력, 모르면 비워두면 QC 가 보완 |
| 부적합 현상 | ✅ | 자유 서술 |
| 사진·영상 | — | 최대 10개 |

> **중요**: 품목코드를 비워도 등록됩니다. 기종명이 임시로 품목 자리에 들어가고, **품질이 나중에 정확한 ERP 코드로 보완**합니다. 작업자 입장에서 "코드를 몰라서 못 올린다" 는 상황이 없어야 함.

### 2-3. 공용 부품 처리 기준

같은 부품이 여러 기종에서 쓰이는 경우:

- 기종명에는 **그 작업에서 조립 중이던 기종**을 적는다 (예: SB-100 조립 중 공용 로드핀 불량 → 기종 "SB-100").
- 부품명은 공용 부품 그대로 적는다.
- 필요 시 비고란에 "공용부품 (SB-100/SB-125 공용)" 과 같이 추가 기재.

## 3. QC 담당자 보완 항목

생산 등록 후 QC 가 현장 확인·조치 결과를 반영해 완성:

- **부품코드** (화성 생산이 비워둔 경우)
- **품목그룹코드**
- **불량유형코드** (A~Z, flaw_type_cd)
- **손실공수** (분 → 시간)
- **거래처**, **부서**, **담당자**
- **조치결과** (act_result), **판정 결과** (decide_result)
- **시정·예방조치** (cap_action)
- **부품비·공임비·클레임금액** (clam_amt)
- **출하일 범위** (출하 후 발견 시)
- **QC 의견** (qa_comment)

생산 등록 → QC 승인(APPROVED) → RPA 가 UNIERP 에 자동 입력 → 저장 확인(ERP_SYNCED).

## 6. 알림 수신 대상

등록 시 수산톡으로 자동 알림. 수신 대상은 관리자가 설정:

- **품질팀** (필수 수신)
- **생산팀 중간 관리자** (필수 수신, 등록자 공장 기준)
- **설계팀** (설계 불량 혐의가 있을 때)
- **구매·외주팀** (업체 불량 혐의가 있을 때)
- **대표이사 등 경영진** (요청 시)

수신 대상에서 빠지거나 추가되고 싶으면 IT/관리자에게 요청.

## 7. 사진·동영상 첨부 규칙

- **사진**: 자동 압축 (약 500 KB 이하), 개수 제한 10개
- **동영상**: 소음·작동 상태 확인용. 용량 제한 적용 (한도 문서 별도)
- **ERP 기준에 맞춰** 개수·용량 설정. 무한 저장 불가.
- 민감한 거래처명·외부 노출 금지 자료 포함 금지

---

## 8. 수정·삭제 권한

- **등록 후 즉시 수정·삭제**: 등록자 본인만 (ERP 미전송 전까지)
- **ERP 전송 이후 수정**: QC 담당자 or 관리자. 감사 로그에 변경 이력 기록
- **삭제**: 관리자 지정자만. 등록 번호는 폐기 처리 (재사용 금지)

## 9. 자주 하는 질문

**Q. 부적합인지 애매할 땐?**
A. **등록하지 않는다**. 품질과 구두로 확인 후 판정이 "부적합" 이면 그때 등록. 등록 후 "아님" 판정 바뀌면 삭제 처리가 번거로움.

**Q. 보통 하루 몇 건 등록하나?**
A. 아산 CR 기준 월 평균 10건 수준. 화성은 공정별 상이. **세세한 작업 수준 불량까지 다 등록하진 않음.**

**Q. 공용 부품이 불량인데 무슨 기종으로 넣을지?**
A. 작업 중이던 기종을 적고, 비고에 "공용부품" 명시. 분석에는 큰 지장 없음.

**Q. 조치가 안 끝났는데 등록해야 하나?**
A. 아니오. 조치 결정 후 등록 원칙. 급한 경우 전화·슈산톡.

**Q. 로드 생산팀도 이 프로그램을 쓰나?**
A. 아니오. 로드 생산팀은 외주 작업자라 대리 등록 어려움 → ERP 직접 등록 유지.

**Q. 출하 부적합도 이걸로?**
A. 현재는 공정 부적합 전용. 출하는 ERP 직접 등록 유지. 향후 확장 검토.
