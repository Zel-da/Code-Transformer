01 · 로그인과 권한

품질 관리자 로그인

회사 이메일 계정

name@soosan.co.kr와 그룹웨어 비밀번호를 사용합니다.

전용 관리자 계정

admin처럼 안내받은 관리자 아이디와 내부 비밀번호를 사용합니다.

메뉴가 보이지 않을 때
QC 등록 또는 관리자 패널이 보이지 않으면 현재 계정의 역할이 일반 등록자일 수 있습니다. 사용자 관리에서 권한을 확인하세요.
02 · 일일 업무

업무 시작 시 확인할 항목

1

관리대장 현황 확인

총 건수, 조치 중, 판정 완료와 지연 건수를 확인합니다.

2

QC 등록의 미완료 목록 확인

접수, 검토 중, 협업 대기 상태 중 우선 처리할 보고서를 찾습니다.

3

경과일 우선순위 확인

5~6일 경과는 주황색, 7일 이상 미처리는 빨간색 경고를 우선 확인합니다.

4

수산톡 요청 확인

신규 접수와 협업 요청 알림을 확인하고 해당 보고서 상세로 이동합니다.

03 · QC 처리 절차

접수부터 승인까지

접수→검토 중→협업 대기(필요 시)→조치 완료→승인 완료→ERP 등록
1

보고서 사실관계 확인

공장, 공정, 품목코드, 발생일, 수량, 현상 설명과 사진이 일치하는지 확인합니다.

2

검토 시작

검토 시작으로 상태를 접수에서 검토 중으로 변경합니다. 다른 담당자에게 현재 처리 중임을 알리는 단계입니다.

3

QC 분석 입력

불량 분류, 원인, 귀책, 조치 방향과 조치 결과를 근거에 따라 작성합니다. 작성 중에는 임시저장 내용을 활용할 수 있습니다.

4

협업 요청

생산·구매·설계 등 확인이 필요하면 담당자를 선택하고 요청 내용을 작성해 협업 대기로 전환합니다.

5

분석 저장

입력값과 첨부 근거를 다시 확인하고 저장합니다. 저장 완료 알림을 확인한 뒤 다음 단계로 진행합니다.

6

조치 완료

실제 현장 조치가 끝나고 결과가 확인된 경우에만 조치 완료로 변경합니다.

7

최종 승인

승인 권한자가 분석과 조치를 검토한 뒤 승인합니다. 승인 완료 후 ERP 자동 등록 준비 상태가 됩니다.

8

ERP 등록 확인

RPA 등록을 실행하고 성공 여부를 확인합니다. 성공하면 상태가 ERP 등록으로 자동 변경됩니다.

중요: 조치 완료와 승인은 단순 진행 표시가 아닙니다. 실제 조치와 검증이 끝난 뒤 변경해야 하며, 승인 완료 후 되돌릴 때는 변경 사유를 남기세요.

06 · 관리대장

검색·상세·RPA 처리

검색과 필터

NCR 번호, 품목명, 모델명으로 검색하고 상태·공장·공정 필터를 조합합니다.

상세 패널

접수 내용, 사진, QC 분석, 처리 상태와 댓글을 한 화면에서 확인합니다.

협업 요청

검토 담당자를 지정하고 요청 내용을 보내면 대상자에게 알림이 발송됩니다.

RPA 등록

승인 완료 보고서에서 RPA 등록을 실행하고 성공·대기·실패 상태를 확인합니다.

RPA 실패 시
바로 반복 실행하지 말고 오류 상태와 입력값을 확인합니다. 재시도 초기화가 필요한 경우 중복 ERP 등록 여부를 먼저 확인하세요.
07 · 관리자 기능

계정과 기준정보 관리

1

사용자 관리

일반 등록자, QC·협업, 관리자, 비활성 계정을 구분해 확인하고 역할과 활성 상태를 관리합니다.

2

CSV 일괄 등록

Outlook CSV를 선택해 신규·기존·제외 인원을 확인한 뒤 실행합니다. 신규 계정만 일반 등록자로 생성되며 기존 권한은 유지됩니다.

3

부서와 알림

부서 코드와 수산톡 Webhook을 확인하고 테스트 전송으로 연결 상태를 검증합니다.

4

보고서 수정·삭제

잘못된 접수 또는 상태를 수정할 수 있습니다. 삭제는 복구할 수 없으므로 NCR 번호와 사유를 다시 확인합니다.

계정 관리 주의: 퇴사자는 삭제보다 비활성화를 우선 사용하세요. 기존 보고서의 등록자 이력을 유지할 수 있습니다.
08 · 문제 해결

운영 중 자주 발생하는 상황

승인을 잘못 눌렀어요

관리자 패널의 보고서 관리에서 상태를 수정하고, 변경 사유를 댓글 또는 감사 이력에 남깁니다.

협업 알림이 가지 않아요

담당자 계정의 활성 상태와 알림 설정, 부서 Webhook 설정을 확인한 뒤 테스트 전송합니다.

피드백 메뉴가 401을 표시해요

다시 로그인하고 브라우저를 새로고침합니다. 계속되면 최신 버전 게시 여부와 인증 토큰 만료를 확인합니다.

화면이 이전 버전으로 보여요

브라우저를 완전히 닫았다 열거나 Ctrl+Shift+R로 새로고침해 서비스 워커 캐시를 갱신합니다.

문의 시 함께 전달할 정보
NCR 번호, 발생 시간, 사용 계정, 오류 문구, 화면 캡처를 함께 전달하면 확인이 빨라집니다. 비밀번호는 전달하지 마세요.

07 · 관리자 기능

계정과 기준정보 관리

1

사용자 관리

일반 등록자, QC·협업, 관리자, 비활성 계정을 구분해 확인하고 역할과 활성 상태를 관리합니다.

2

CSV 일괄 등록

Outlook CSV를 선택해 신규·기존·제외 인원을 확인한 뒤 실행합니다. 신규 계정만 일반 등록자로 생성되며 기존 권한은 유지됩니다.

3

부서와 알림

부서 코드와 수산톡 Webhook을 확인하고 테스트 전송으로 연결 상태를 검증합니다.

4

보고서 수정·삭제

잘못된 접수 또는 상태를 수정할 수 있습니다. 삭제는 복구할 수 없으므로 NCR 번호와 사유를 다시 확인합니다.

계정 관리 주의: 퇴사자는 삭제보다 비활성화를 우선 사용하세요. 기존 보고서의 등록자 이력을 유지할 수 있습니다.

02 · 일일 업무

업무 시작 시 확인할 항목

1

관리대장 현황 확인

총 건수, 조치 중, 판정 완료와 지연 건수를 확인합니다.

2

QC 등록의 미완료 목록 확인

접수, 검토 중, 협업 대기 상태 중 우선 처리할 보고서를 찾습니다.

3

경과일 우선순위 확인

5~6일 경과는 주황색, 7일 이상 미처리는 빨간색 경고를 우선 확인합니다.

4

수산톡 요청 확인

신규 접수와 협업 요청 알림을 확인하고 해당 보고서 상세로 이동합니다.

03 · QC 처리 절차

접수부터 승인까지

접수→검토 중→협업 대기(필요 시)→조치 완료→승인 완료→ERP 등록
1

보고서 사실관계 확인

공장, 공정, 품목코드, 발생일, 수량, 현상 설명과 사진이 일치하는지 확인합니다.

2

검토 시작

검토 시작으로 상태를 접수에서 검토 중으로 변경합니다. 다른 담당자에게 현재 처리 중임을 알리는 단계입니다.

3

QC 분석 입력

불량 분류, 원인, 귀책, 조치 방향과 조치 결과를 근거에 따라 작성합니다. 작성 중에는 임시저장 내용을 활용할 수 있습니다.

4

협업 요청

생산·구매·설계 등 확인이 필요하면 담당자를 선택하고 요청 내용을 작성해 협업 대기로 전환합니다.

5

분석 저장

입력값과 첨부 근거를 다시 확인하고 저장합니다. 저장 완료 알림을 확인한 뒤 다음 단계로 진행합니다.

6

조치 완료

실제 현장 조치가 끝나고 결과가 확인된 경우에만 조치 완료로 변경합니다.

7

최종 승인

승인 권한자가 분석과 조치를 검토한 뒤 승인합니다. 승인 완료 후 ERP 자동 등록 준비 상태가 됩니다.

8

ERP 등록 확인

RPA 등록을 실행하고 성공 여부를 확인합니다. 성공하면 상태가 ERP 등록으로 자동 변경됩니다.

중요: 조치 완료와 승인은 단순 진행 표시가 아닙니다. 실제 조치와 검증이 끝난 뒤 변경해야 하며, 승인 완료 후 되돌릴 때는 변경 사유를 남기세요.
04 · 분석 품질

QC 입력 항목 작성 기준

항목작성 기준확인할 근거
불량 분류외관·치수·기능·재료 등 실제 현상에 맞는 항목 선택사진, 측정값, 검사 결과
원인 분석현상 반복이 아니라 발생 원인과 유출 원인을 구분해 구체적으로 작성작업 조건, 설비, 자재 LOT, 도면
조치 방향업체 방문 수정, 생산팀 자체 수정, 반출 후 수정 입고 등 실제 방향 선택담당 부서 합의, 일정
조치 결과누가, 언제, 무엇을, 몇 개 처리했고 확인 결과가 어땠는지 작성재검 결과, 완료 사진
시정·예방조치재발 방지 활동의 필요 여부와 진행 상태 기록표준서 변경, 교육, 설비 개선
부적합 제외실제 부적합이 아니어서 ERP 등록 대상에서 제외할 때만 선택제외 사유와 판정 근거
좋은 조치 결과 예
“9월 16일 생산팀에서 대상 12EA 전수 재체결 완료. 토크렌치 85N·m 확인 후 마킹했으며 재검 결과 이상 없음.”

02 · 일일 업무

업무 시작 시 확인할 항목

1

관리대장 현황 확인

총 건수, 조치 중, 판정 완료와 지연 건수를 확인합니다.

2

QC 등록의 미완료 목록 확인

접수, 검토 중, 협업 대기 상태 중 우선 처리할 보고서를 찾습니다.

3

경과일 우선순위 확인

5~6일 경과는 주황색, 7일 이상 미처리는 빨간색 경고를 우선 확인합니다.

4

수산톡 요청 확인

신규 접수와 협업 요청 알림을 확인하고 해당 보고서 상세로 이동합니다.

03 · QC 처리 절차

접수부터 승인까지

접수→검토 중→협업 대기(필요 시)→조치 완료→승인 완료→ERP 등록
1

보고서 사실관계 확인

공장, 공정, 품목코드, 발생일, 수량, 현상 설명과 사진이 일치하는지 확인합니다.

2

검토 시작

검토 시작으로 상태를 접수에서 검토 중으로 변경합니다. 다른 담당자에게 현재 처리 중임을 알리는 단계입니다.

3

QC 분석 입력

불량 분류, 원인, 귀책, 조치 방향과 조치 결과를 근거에 따라 작성합니다. 작성 중에는 임시저장 내용을 활용할 수 있습니다.

4

협업 요청

생산·구매·설계 등 확인이 필요하면 담당자를 선택하고 요청 내용을 작성해 협업 대기로 전환합니다.

5

분석 저장

입력값과 첨부 근거를 다시 확인하고 저장합니다. 저장 완료 알림을 확인한 뒤 다음 단계로 진행합니다.

6

조치 완료

실제 현장 조치가 끝나고 결과가 확인된 경우에만 조치 완료로 변경합니다.

7

최종 승인

승인 권한자가 분석과 조치를 검토한 뒤 승인합니다. 승인 완료 후 ERP 자동 등록 준비 상태가 됩니다.

8

ERP 등록 확인

RPA 등록을 실행하고 성공 여부를 확인합니다. 성공하면 상태가 ERP 등록으로 자동 변경됩니다.

중요: 조치 완료와 승인은 단순 진행 표시가 아닙니다. 실제 조치와 검증이 끝난 뒤 변경해야 하며, 승인 완료 후 되돌릴 때는 변경 사유를 남기세요.

계정 관리 주의: 퇴사자는 삭제보다 비활성화를 우선 사용하세요. 기존 보고서의 등록자 이력을 유지할 수 있습니다.

03 · QC 처리 절차

접수부터 승인까지

접수→검토 중→협업 대기(필요 시)→조치 완료→승인 완료→ERP 등록
1

보고서 사실관계 확인

공장, 공정, 품목코드, 발생일, 수량, 현상 설명과 사진이 일치하는지 확인합니다.

2

검토 시작

검토 시작으로 상태를 접수에서 검토 중으로 변경합니다. 다른 담당자에게 현재 처리 중임을 알리는 단계입니다.

3

QC 분석 입력

불량 분류, 원인, 귀책, 조치 방향과 조치 결과를 근거에 따라 작성합니다. 작성 중에는 임시저장 내용을 활용할 수 있습니다.

4

협업 요청

생산·구매·설계 등 확인이 필요하면 담당자를 선택하고 요청 내용을 작성해 협업 대기로 전환합니다.

5

분석 저장

입력값과 첨부 근거를 다시 확인하고 저장합니다. 저장 완료 알림을 확인한 뒤 다음 단계로 진행합니다.

6

조치 완료

실제 현장 조치가 끝나고 결과가 확인된 경우에만 조치 완료로 변경합니다.

7

최종 승인

승인 권한자가 분석과 조치를 검토한 뒤 승인합니다. 승인 완료 후 ERP 자동 등록 준비 상태가 됩니다.

8

ERP 등록 확인

RPA 등록을 실행하고 성공 여부를 확인합니다. 성공하면 상태가 ERP 등록으로 자동 변경됩니다.

중요: 조치 완료와 승인은 단순 진행 표시가 아닙니다. 실제 조치와 검증이 끝난 뒤 변경해야 하며, 승인 완료 후 되돌릴 때는 변경 사유를 남기세요.
