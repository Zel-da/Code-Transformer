# NCR SSO 확인·조치 회신

점검: 2026-10-27 13:10 KST 운영 HTTP 점검 및 이후 개발 환경 시험.

## 운영 반영

현재 운영 서버에는 SSO 시작·콜백 경로가 존재하며 설정 활성 상태입니다.
이번 보완의 운영 반영 일시: 미반영, 게시 필요.
기존 Client ID·Secret과 중앙 설정은 변경하지 않았습니다.

## 실제 주소

- 시작: https://code-transformer.replit.app/api/auth/sso/login
- 콜백: https://code-transformer.replit.app/api/auth/sso/callback
- 중앙 인증: https://ssc-dashboardhub.replit.app/sso/authorize

운영 시작 응답의 Client ID는 요청서와 일치했습니다.
시작 요청은 302이며 response_type=code, 요청별 state, 정확한 redirect_uri를 전달합니다.
쿠키의 Secure, HttpOnly, SameSite=Lax, Path=/api를 확인했습니다.
state는 공유 DB에서 5분간 보존하고 콜백에서 원자적으로 1회 소비합니다.

## 이번 조치

- 코드 교환에 빠져 있던 grant_type=authorization_code 추가.
- 인증 시작과 동일한 redirect_uri 사용을 시험으로 확인.
- 실패 로그에 안전한 단계와 HTTP 상태 기록. 코드·토큰·이메일·쿠키·Secret은 기록하지 않음.
- 미등록 사용자 자동 승인 금지, 기존 NCR 역할 유지.

## 시험 결과

운영 서버:

| 점검 | 결과 |
| --- | --- |
| SSO 설정 조회 | 200, 활성 |
| SSO 시작 | 302, 제공자·Client ID·콜백 일치 |
| state·쿠키 없는 콜백 | 400 차단 |
| 미인증 사용자 정보 조회 | 401 차단 |

운영 DB는 개인정보 없는 집계만 읽었습니다.
중앙 계정 연결 기록 2건, 저장된 앱 인증 세션 0건, 미만료 앱 인증 세션 0건입니다.
연결 기록만으로 브라우저 최종 접속 성공을 판정하지 않습니다.

개발 환경의 모의 중앙 제공자와 임시 NCR 계정으로 SSO 전용 시험 16개 통과:
정상 콜백 후 앱 세션으로 보호 API 접근, 기존 역할 유지·승격 방지,
로그아웃 후 재로그인, 앱 세션 만료, 미등록·비활성 계정 차단,
state 누락·변조·만료·재사용, 중복 시작 시 이전 요청 무효화,
제공자가 만료·재사용 코드를 거부할 때 재교환하지 않음,
aud/sub 불일치, 중앙 장애, 중앙 계정 거부, 로그아웃 Origin 검사.
임시 계정·연결·세션은 정리했습니다. 서버 타입 검사 통과.

## 미해결 / 검증 한계

1. 이번 보완을 게시해야 운영 코드에 적용됩니다.
2. 실제 중앙 계정을 통한 브라우저 로그인 → 콜백 → NCR 보호 화면 →
   새로고침 → 로그아웃 → 재로그인의 운영 종단 시험은 수행하지 못했습니다.
   실제 계정의 로그인 수단이 없으며, 모의 시험을 운영 성공으로 보고하지 않습니다.
3. 중앙의 실제 코드 300초 만료·재사용 거부는 모의 거부 응답으로만 확인했습니다.
   중앙 실제 토큰 발급 건수는 요청서의 정보이며 별도로 조회하지 않았습니다.
4. 최초 명령이 전체 서버 시험을 실행하여 SSO와 별개인 ERP 시험 8개도 실패했습니다.
   ERP 데이터 조회 실패는 이번 SSO 수정 범위에서 다루지 않았습니다.
