---
name: QC 검토 작업 원칙
description: QC 담당자의 과거 사용 문의와 검토 단계 삭제 범위 결정 배경
---

QC 담당자는 일반 관리자와 별개로 QC 목록 메뉴에 접근해야 하며, QC 분석은 신규 보고서 생성이 아니라 기존 보고서 수정임을 명확히 안내합니다.

**Why:** 사용자가 전달한 QC 담당자 피드백에서 목록 메뉴가 보이지 않고 기존 보고서 수정 화면을 신규 입력으로 오해했습니다.

**How to apply:** 역할별 내비게이션과 가이드를 변경할 때 검토자·승인자 경로를 관리자 경로와 별도로 확인합니다.

삭제는 검토 중 보고서에 한정하며, 관리자에게도 잠금·ERP 처리 보호를 적용합니다. 삭제 전 경고하고 감사 기록은 보존합니다.

**Why:** 사용자는 데이터 검토 단계의 수정·삭제를 요청했으며, 완료된 품질 판단이나 ERP 처리 기록을 삭제하는 범위까지 요청한 것은 아닙니다.

**How to apply:** 접수·협업·완료·승인 단계까지 삭제 범위를 넓히거나 관리자 예외를 추가하려면 별도 정책 확인이 필요합니다.
