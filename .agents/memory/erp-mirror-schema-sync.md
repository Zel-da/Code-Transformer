---
name: ERP 미러 테이블과 개발 DB 스키마 동기화
description: 외부 PC의 ERP 동기화 스크립트가 운영 DB에 직접 만든 테이블·뷰를 개발 DB에도 맞춰야 하는 이유
---

ERP 동기화 스크립트(erp_query, 사내 PC에서 실행)를 운영하는 담당자는 새 테이블·뷰를 운영 DB에 SQL로 직접 만들 수 있습니다. 같은 구조를 개발 DB에도 만들어 두어야 합니다.

**Why:** 게시할 때 개발 DB 스키마를 기준으로 운영 DB와의 차이를 반영합니다. 개발 DB에 없는 운영 테이블은 삭제 대상으로 제안될 수 있습니다. 과거 ERP 부적합 이력 테이블과 통합 조회 뷰가 운영에만 있던 사례가 있었습니다. 개발 DB에서 drizzle push를 실행하면 보고서 번호 고유 제약 질문에서 대화형으로 멈춥니다.

**How to apply:** Git으로 스키마 파일이 추가되면 운영과 개발 DB에서 해당 테이블 존재 여부를 읽기 전용으로 비교합니다. 개발에만 없으면 운영 정의(컬럼·인덱스·뷰 정의)를 그대로 개발 DB에 생성합니다. 기존 보고서 테이블을 truncate하는 선택지는 고르지 않습니다.
